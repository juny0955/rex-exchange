이 문서는 `amend-decrease-qty` 시나리오의 첫 기준선을 기록한다.
고정 측정 환경은 [Stress 테스트 홈](../../../../README.md)의 Vultr EPYC-Rome 환경을 사용한다.

## 요약

`amend-decrease-qty` 단일 심볼 기준으로 500k commands/s까지는 측정 구간에서 채널 포화 없이 처리됐다.
700k부터 850k commands/s까지는 channel full이 반복적으로 발생했지만 accepted/s와 published/s가 target/s에 가깝게 유지됐다.
900k commands/s에서는 accepted/s가 약 630k/s로 하락해 명확한 초과 구간으로 본다.

이 시나리오는 Place/Amend/Cancel 3-command 묶음으로 orderbook에 주문을 넣고, 같은 가격에서 수량만 줄인 뒤, 같은 주문을 제거한다.
체결 수와 maker 갱신 수는 모두 0이며, 반복 종료 시 orderbook이 비워지는 stationary 정정 경로 시나리오다.

| 항목 | 값 |
| --- | ---: |
| 안정 TPS | 500,000 commands/s |
| 경계 TPS | 700,000-850,000 commands/s |
| 초과 구간 | 900,000+ commands/s |

## 해석 포인트

- 200k, 500k는 측정 구간에서 채널 포화가 없으므로 안정권으로 본다.
- 700k는 3회 모두 channel full이 발생했으므로 무손실 안정권은 아니지만 accepted/s는 target/s에 가깝다.
- 750k, 800k, 850k도 소량 channel full이 발생해 경계 구간으로 본다.
- 900k는 accepted/s가 약 630k/s로 하락해 명확한 초과 구간이다.
- 주문 접수, 주문 정정, 주문 취소 결과가 거의 1:1:1로 발생하므로 Place/Amend/Cancel 묶음이 정상적으로 처리됐다.
- 체결 수와 maker 갱신 수는 모두 0이므로 이 결과는 matching sweep 비용이 아니라 orderbook 삽입, in-place 정정, 삭제 비용을 본다.
- `completed = yes`는 접수된 command가 결과 발행까지 완료됐다는 뜻이다. channel full로 거부된 command가 처리됐다는 의미는 아니다.
