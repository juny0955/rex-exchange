이 문서는 `amend-price-change` 시나리오의 첫 기준선을 기록한다.
고정 측정 환경은 [Stress 테스트 홈](../../../../README.md)의 Vultr EPYC-Rome 환경을 사용한다.

## 요약

`amend-price-change` 단일 심볼 기준으로 300k commands/s까지는 측정 구간에서 채널 포화 없이 처리됐다.
500k부터 700k commands/s까지는 channel full이 발생했지만 accepted/s와 published/s가 target/s에 가깝게 유지됐다.
800k commands/s 이상에서는 accepted/s가 크게 하락해 명확한 초과 구간으로 본다.

이 시나리오는 Place/Amend/Cancel 3-command 묶음으로 orderbook에 주문을 넣고, 가격 변경 정정으로 cancel-replace 경로를 탄 뒤, 같은 주문을 제거한다.
체결 수와 maker 갱신 수는 모두 0이며, 반복 종료 시 orderbook이 비워지는 stationary 정정 경로 시나리오다.

| 항목 | 값 |
| --- | ---: |
| 안정 TPS | 300,000 commands/s |
| 경계 TPS | 500,000-700,000 commands/s |
| 초과 구간 | 800,000+ commands/s |

## 해석 포인트

- 300k는 측정 구간에서 채널 포화가 없으므로 안정권으로 본다.
- 500k, 600k, 700k는 channel full이 발생했으므로 무손실 안정권은 아니지만 accepted/s는 target/s에 가깝다.
- 800k 이상은 accepted/s가 크게 하락해 명확한 초과 구간이다.
- 주문 접수, 주문 정정, 주문 취소 결과가 거의 1:1:1로 발생하는 구간에서는 Place/Amend/Cancel 묶음이 정상적으로 처리됐다.
- 800k 이상에서는 channel full이 커지면서 Place/Amend/Cancel 비율도 흐트러지므로 초과 구간 해석에 포함한다.
- 같은 정정 계열인 `amend-decrease-qty`보다 낮은 target/s에서 초과 구간에 진입하므로, 가격 변경 cancel-replace 경로가 더 무거운 부하로 관측된다.
- 체결 수와 maker 갱신 수는 모두 0이므로 이 결과는 matching sweep 비용이 아니라 orderbook 삽입, 가격 변경 정정, 삭제 비용을 본다.
- `completed = yes`는 접수된 command가 결과 발행까지 완료됐다는 뜻이다. channel full로 거부된 command가 처리됐다는 의미는 아니다.
