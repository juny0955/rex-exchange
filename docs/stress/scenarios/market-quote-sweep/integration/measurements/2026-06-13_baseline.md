## 판정

- **안전 TPS = 80,000**. `채널 포화 비율 0.154%`로 거의 무손실이며, ack p99 `983µs`, E2E p99 `14.511ms`로 안정적이다. `full-fill-same-level`(commands/unit=11, 동일)의 100k 대비 503 비율이 더 높아, 동일 unit 크기라도 시장가 스윕의 엔진 처리 비용이 약간 더 크다는 신호다.
- **경계 TPS = 100,000**. `target 달성률 100%`는 유지하지만 `채널 포화 0.744%`, ack p99가 `983µs → 41.890ms`로 40배 이상 급증한다. `full-fill-same-level`의 100k(안전)보다 일찍 경계에 도달한다.
- **포화 TPS = 130,000**. `채널 포화 16.91%`, `target 달성률 91.88%`(부하 생성기가 목표 유입률을 못 따라감, pacing 최대 지연 2.416s)이며, **무손실 판정이 처음으로 실패**했다 — `settle 완료 = 아니오`, 누락 584,158건. 이는 15초 settle 제한 시간 내에 Kafka 이벤트가 도착하지 못한 것으로, 실제 데이터 손실이 아니라 과부하로 인한 처리 지연이 settle 윈도우를 초과했음을 의미한다(E2E p99 `167.695ms`).
- 같은 commands/unit=11인 `full-fill-same-level`(안전 100k/경계 120k/포화 150k+)과 비교하면, `market-quote-sweep`은 시장가 체결 시 가격대별 호가 순회·체결 계산 비용이 더 커서 **전 구간이 한 단계씩 낮게 형성**된다.
