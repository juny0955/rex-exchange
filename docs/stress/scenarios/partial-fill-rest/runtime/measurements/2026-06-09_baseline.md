이 문서는 `partial-fill-rest` 시나리오의 첫 기준선을 기록한다.
고정 측정 환경은 [Stress 테스트 홈](../../../../README.md)의 Vultr EPYC-Rome 환경을 사용한다.

## 요약

`partial-fill-rest` 단일 심볼 기준으로 50k commands/s까지는 채널 포화 없이 처리됐다.
55k commands/s부터 channel full이 발생했으므로 55k 이상은 무손실 안정권으로 보지 않는다.

이 시나리오는 GTC taker 잔량을 orderbook에 남기는 동작을 포함한다.
반복 실행 중 이전 반복의 잔존 주문이 다음 반복의 반대편 주문과 교차되므로 orderbook 상태가 시간에 따라 drift한다.
따라서 아래 TPS는 현 구현의 non-stationary workload 관측값이며, `full-fill-same-level`, `market-quote-sweep` 기준선과 직접 비교하지 않는다.

| 항목 | 값 |
| --- | ---: |
| 안정 TPS | 50,000 commands/s |
| 경계 TPS | 55,000 commands/s |
| 초과 구간 | 55,000+ commands/s |

## 해석 포인트

- 50k는 채널 포화가 없으므로 현 구현 기준 안정권으로 본다.
- 55k부터 channel full이 발생해 무손실 안정권으로 보지 않는다.
- 60k 이상에서는 accepted/s가 약 54k-58k/s 부근에 머물며 channel full이 빠르게 증가한다.
- 100k 이상에서는 dispatch 시도량은 목표에 가깝지만 accepted/s가 약 55k/s 수준으로 제한된다.
- 이 결과는 잔존 주문이 누적되는 non-stationary workload의 관측값이다.
- `completed = yes`는 접수된 command가 결과 발행까지 완료됐다는 뜻이다. channel full로 거부된 command가 처리됐다는 의미는 아니다.
