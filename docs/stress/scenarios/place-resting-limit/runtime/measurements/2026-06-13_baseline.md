## 판정

- 최신 안정 TPS는 `20,000`이다. `채널 포화 = 0`, `완료 여부 = 예`, `발행 결과 = 접수 성공`을 만족한다.
- 경계 TPS는 `30,000`이다. 채널 포화 434건이 발생하며 성능 저하가 시작되는 지점이다.
- 초과 구간은 `50,000+`이다. 고부하 시 Docker 환경 리소스 제한(Memory)으로 인해 프로세스가 강제 종료(Exit 137)될 위험이 있으므로 측정 시간을 단축하여 수행했다.
- `place-resting-limit` 시나리오는 GTC 주문을 orderbook에 계속 쌓는 non-stationary 특성을 가진다. 주문이 누적될수록 orderbook 관리 오버헤드가 증가하여 다른 시나리오 대비 상당히 낮은 안정 TPS(20,000)를 보여준다.
- 80,000 TPS 이상에서는 메모리 부족으로 인해 측정이 불가함을 확인했다.
