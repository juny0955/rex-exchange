이 문서는 `place-resting-limit` 시나리오의 첫 기준선을 기록한다.
고정 측정 환경은 [Runtime Stress 위키 홈](../../../README.md)의 Vultr EPYC-Rome 환경을 사용한다.

## 요약

`place-resting-limit` 단일 심볼 기준으로 10k commands/s까지는 채널 포화 없이 처리됐다.
15k commands/s부터 channel full이 발생했으므로 15k 이상은 무손실 안정권으로 보지 않는다.

이 시나리오는 체결 없이 GTC limit 주문을 orderbook에 계속 남기는 동작을 포함한다.
반복 실행 중 잔존 주문 수가 계속 증가하므로 orderbook 상태가 시간에 따라 drift한다.
따라서 아래 TPS는 현 구현의 non-stationary workload 관측값이며, `full-fill-same-level`, `market-quote-sweep` 기준선과 직접 비교하지 않는다.

| 항목 | 값 |
| --- | ---: |
| 안정 TPS | 10,000 commands/s |
| 경계 TPS | 15,000 commands/s |
| 초과 구간 | 15,000+ commands/s |

## 해석 포인트

- 10k는 채널 포화가 없으므로 현 구현 기준 안정권으로 본다.
- 15k부터 channel full이 발생해 무손실 안정권으로 보지 않는다.
- 50k 이상에서는 accepted/s가 target/s보다 낮게 유지되며 channel full이 계속 발생한다.
- 체결 수와 maker 갱신 수는 모두 0이므로 이 결과는 matching sweep 비용이 아니라 미체결 GTC 주문 누적 비용을 본다.
- 이 결과는 잔존 주문이 누적되는 non-stationary workload의 관측값이다.
- `completed = yes`는 접수된 command가 결과 발행까지 완료됐다는 뜻이다. channel full로 거부된 command가 처리됐다는 의미는 아니다.
